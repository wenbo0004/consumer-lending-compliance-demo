# Consumer Lending Compliance Monitoring Demo — Starter

This repository is an exercise starter, not a completed monitoring system. All names, jurisdictions, records, thresholds, and rules are synthetic and fictional. They do not describe any real lending law or company policy.

## Goal

Build a small, explainable workflow: source data → population → SQL controls → validation → exception output → dashboard → human investigation.

## Included source data

- `data/applications.csv`: application ID, submission date, decision, decision date, notice date, reason code.
- `data/loans.csv`: loan ID, linked application ID, jurisdiction, status, origination date, APR percentage.
- `scripts/generate_data.py`: deterministic generator for these two CSVs. The files are already included so you can inspect them before running code.
- `requirements.txt`: dashboard packages to install in the cloud environment.

## Fictional design brief

1. **APR control:** Funded loans in fictional jurisdiction MIRA must have APR at or below **24.00%**. Specify exclusions for records that cannot be evaluated reliably.
2. **Notice control:** Declined applications need a notice within **five calendar days** after decision, with a populated reason code. Decide when a missing notice is overdue relative to an as-of date.
3. **Data quality:** Identify duplicate application and loan IDs, missing decisions/dates, notice dates before decisions, invalid APR values, and loans without matching applications.

Use `2026-06-30` as the initial as-of date. A record exactly on a limit should pass; one beyond it should fail. Preserve evaluated passing records and excluded records so the denominator can be reconciled.

## What we will build together

1. Inspect the two CSVs and define each control's population and grain.
2. Write the three SQL queries in `sql/`.
3. Write a Python runner in `scripts/` that loads CSVs into SQLite, executes controls, validates counts and boundaries, and writes `output/` files.
4. Create a one-page `dashboard.py` with KPIs, exceptions by control, source-event trend, and a review table.
5. Replace this starter README with a portfolio walkthrough covering requirement → population → source of truth → rule → exception → investigation/remediation/evidence.

The final outputs must be generated by your runner; none are provided in this starter.
